# AVED 性能与余额边界审计 · 2026-11-07

基线为 `c6dc3d5`，目标为 2 核、2 GB、最多 120 个账号和约 40 人同时在线。

## 已处理

- 聊天心跳原来由每个连接广播给整个房间；改为仅刷新当前连接。发言仍立即广播，删除/审核后的聊天记录最多 20 秒刷新。增加同账号连接上限和慢连接缓冲保护。
- 速降同步从每 500 ms 改为每 1000 ms，保留精确揭晓定时器。前端仍用时间戳绘制运动、倒计时；健康 SSE 不再额外周期拉取 `/current`。赛马公共轨迹和历史每轮广播只计算一次。
- 常用余额读取复用 SQLite 触发器维护的 `personal_metrics.balance`，在每次服务启动时与账本核对重建当前余额。入账和快照在同一事务内变更；没有把余额缓存到浏览器或独立的异步计数器。
- 聊天、留言、未成交订单、待结算乘员及爱心账户增加相关索引。现代持仓查询跳过旧版全量交易/日志回溯及重复的表结构检查。
- 玩家登录只取个人 bootstrap。通告、名录、收容、论坛、生活标签和娱乐数据按页面首次进入加载，音乐清单首次播放才取。相同并发 GET 合并；写请求不自动重试或合并。
- 玩家设计配置不再由每次 body class 变化触发请求；普通员工不再每 10 秒轮询设计配置。管理端后台标签不再每 5 秒探活。
- 静态内容支持 ETag、304、HEAD、gzip 和有界缓存（16 MiB）；大文件用流传输。在线文本编辑的 revision 参与缓存键，保存后仍可立即读取新文案。
- 20 张旧 PNG/JPEG 中，11 张仍使用的位图由 **3,192,267 B → 478,558 B（约 -85.0%）**。另删去 9 张未被页面代码引用的大图；原图可从 Git 历史恢复。WebP 使用内容摘要文件名，允许长期缓存。没有重构任何用户头像原图。
- 头像默认复用 256 像素缓存派生图；牌桌和速降复用 64 像素派生图。版本摘要有界缓存，图片解码限制为 2 个并发和 8 个等待者。
- 登录页不再预载内页图标，外部字体样式只在登录后挂载。大体积设计字体保留用于既有设计资料，没有加入登录加载链。Tailwind 浏览器运行时替换为已编译的本地 CSS。
- 管理员创建/重置账号的密码派生改为异步，且在数据库事务外计算；密码工作限制为 2 个并发、48 个排队。登录有 IP 请求上限，游戏/交易/聊天有每账号短时突发限制，未成交挂单最多 100 笔。

## 余额与功能边界

- 服务端决定随机数、价格、输赢、投入、派奖和账本；客户端提交动作，不能提交最终余额或让服务端接受自行改写的派奖数额。
- 修复股票开仓缺少可用资金检查的问题；仍允许平掉亏损仓位，保留已有负债和主动归零规则。
- 新牌桌是练习模式。停用仍能发放每次 20,000 积分的旧 `/api/player/games/cards` 接口（410），删除旧牌桌引擎；既有历史记录保留。
- 刮刮乐重复 requestKey 仍仅结算一次；捐赠、签到、速降和赛马继续使用原有事务/唯一键/已结算状态保护。没有降低这些校验。
- 这不是严格反机器人系统：脚本仍可能自动执行合法玩法。前端显示数值可被本地改写，但不作为余额入账依据。

## 后续维护

- 修改 HTML/JS 中的 Tailwind class 后运行 `npm run build:css`，将生成的 `public/terminal-utilities.css` 一起提交。生产只安装运行依赖，无需线上构建 CSS。
- 新站内位图可用 `node tools/optimize-images.mjs` 转换；检查静态和动态引用并做视觉检查后提交。
- 当前余额依赖只追加账本。直接用 SQL 修改/删除旧账本不是正常管理流程，必须停服维护并在重启后核对；后台余额调整继续通过新增流水完成。
- 保留全部真实账号、头像、账本、帖子、历史游戏记录及设计资料。没有为减少磁盘占用清除审计数据；长期规模增长时应另行定义归档策略。
