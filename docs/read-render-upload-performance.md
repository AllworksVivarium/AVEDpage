# 公共读取、换票与上传优化 — 2026-11-11

## 行情与联机读取

公共报价、开盘涨跌幅、相同证券/周期的 K 线及播报复用有界内存快照。SQLite total_changes/data_version 与上海交易日期用来失效；交易量、直接写库、其他连接写库、日期变化、重启均会重新生成。事务中的读取不填入缓存，回滚不得泄漏未提交价格或成交量。缓存响应复制后返回；个人成交标记与持仓、余额仍逐账户读取。行情依旧由服务器每 5 秒更新，交易和结算立即持久化。

竞速每次广播批量读取本局委托与个人大奖，速降每次广播一次读取上一局结果及大奖，再按账户组装。内部 Map 不进入公共 JSON；开伞令牌、未揭示安全线/种子仍按原规则保护。余额不跨广播缓存，SSE 仍负责推送。

本地同一代码/周期、同一报价周期内连续 60 次公共行情读取（已预热）：SQL 执行从 540 次降为 360 次，其中公共价格/K 线/基准表访问从 420 次降为 0 次，指数写入尝试从 60 次降为 0 次。一次本地内存 SQLite 测量为 5.24ms → 0.69ms。剩余主要为版本计数器检查；不代表零 SQL、生产 CPU 占用或全站并发保证。

## 刮刮乐

已刮开的格子保留原遮盖节点，换票时按网格批量装回，避免重新解析 SVG/HTML。最多保留 64 个遮盖节点；票型、格子数量、价格等变化仍正确处理。下一张始终是免费本地草稿，首次刮开仍由服务器扣款并产生结果，不提前领取真实票券，不改变概率。连续彩带层的原有数量上限保留。

一次本地浏览器简化票面、100 次已刮开 → 下一张（包含强制布局）的重置时间：29.2ms → 21.9ms。该诊断不等同于手机整页帧率，也未假定所有卡顿都已消失。服务器首刮请求仍受网络往返影响。

## 图片上传

玩家头像、论坛附图、生活记录，以及管理端个人头像共用 image-upload.js。原始文件上限 20MB / 1600 万像素；头像最长边 512，其他图片最长边 1536，目标最大 800,000 字节。按比例缩放、保留透明度与方向，编码 WEBP，必要时降低质量及尺寸。小图可原样提交；无法处理时显示错误。浏览器释放 ImageBitmap 与 Canvas 内存。服务器原有格式/大小/像素校验和有界队列保留。

本地真实浏览器用 2400×1600 随机像素 PNG（13,212,025 字节）核对：附图变为 1229×819 / 518,916 字节，头像为 512×341 / 64,242 字节。服务端继续完成头像裁剪及缩略图生成。该高噪声测试仅验证限额与编码，非画质基准。

发布前全量 Node 测试 245/245 通过，并用真实浏览器无购买诊断核对换票与编码。演示诊断页面不发布到服务器。
